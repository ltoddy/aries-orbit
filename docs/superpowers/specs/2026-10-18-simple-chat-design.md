# Aries Orbit 首版对话设计

Aries Orbit 是使用 Rust 和 GPUI 构建的本地 Agent 桌面客户端。首版围绕已有的 `aries acp` 实现简单对话，界面由左侧导航栏和主对话区域组成。完成标准是用户能启动应用、新建对话、发送消息并看到真实 Agent 的流式回复。

## 已确认需求与默认选择

用户已确认：面向本地代码仓库，使用现有 Aries Agent；首版只实现简单对话，采用左侧导航栏和主对话区域的两栏布局。

以下为本版默认选择，供审阅：先在 macOS 验证；沿用现有 `gpui-kit 0.7.3` 和 Rust 2024；使用深色中性配色；会话列表和展示记录保存在本次应用运行的内存中；工作目录默认为启动应用时的目录，也允许通过一个命令行目录参数指定。界面显示当前目录名及完整路径，创建 ACP 会话时传递绝对路径。

## 界面与交互

窗口初始尺寸约为 1100 × 760，最小尺寸为 760 × 520。左侧导航栏宽约 240，主对话区域占据其余空间。

### 左侧导航栏

- 顶部显示 Aries Orbit 名称和“新建对话”按钮。
- 中部显示当前运行期间的会话列表，选中会话有明确高亮。
- 新会话初始标题为“新对话”，发送首条消息后以消息的第一行生成简短标题。
- 底部显示当前工作目录及 Agent 的连接状态。
- 新建与切换会话保留各自的消息和输入草稿。

### 主对话区域

- 顶部显示当前会话标题。
- 空会话显示简短欢迎文案，底部输入框可直接输入。
- 消息区域区分用户与 Aries，支持长文本换行、滚动和 Markdown 基础显示。
- 底部为多行输入框；Enter 发送，Shift+Enter 换行；中文输入法确认候选词时不发送。
- 输入为空或仅包含空白时不允许发送。
- 发送后立即展示用户消息及等待状态；Agent 文本增量合并到当前回复。
- 回复期间提供停止按钮，停止后保留已有内容，等待 Agent 确认结束后才能再次发送。
- 本版同时只运行一轮请求。其他会话仍可浏览和编辑草稿，发送按钮在当前轮结束后恢复。
- 用户停留在消息底部时跟随流式内容滚动；向上阅读时保持其滚动位置。

## ACP 接入

应用管理一个 `aries acp` 子进程，使用默认 ACP v1 和 stdio。优先通过 PATH 定位 `aries`；兼顾桌面启动环境，尝试用户目录下的 `.cargo/bin/aries`。找不到时显示可理解的错误和重连入口。

应用启动时建立连接并完成 `initialize`。用户第一次发送某个新对话的消息时，调用 `session/new` 获取远端 session ID，然后调用 `session/prompt`。后续轮次复用同一 ID。接收 `session/update` 中的 Agent 文本增量；最终状态以 `session/prompt` 的结果为准。停止按钮发送 `session/cancel`。

通知可能在 `session/new` 返回之前到达：按远端 session ID 缓存这些更新，绑定本地会话后按顺序应用。所有事件通过会话 ID 路由，切换导航不能把回复写进另一个会话。

工具执行期间显示简短活动状态，文本回复与工具输出分开处理。若 Agent 发起权限请求，在主对话区域显示它提供的选项，由用户选择后回复；取消或关闭应用时结束待处理请求。

Agent 进程、标准流读写和协议请求在后台运行。UI 主线程只处理界面状态与用户事件。连接需要持续接收通知，不能因等待 prompt 结果而阻塞取消请求。

## 状态与错误处理

连接状态区分连接中、已连接和连接失败；会话状态区分空闲、创建中、回复中和停止中。

- 创建会话或发送失败：显示错误，保留输入或已显示的用户消息，允许恢复后继续操作。
- 回复过程中断：保留部分回复并标明中断，不显示为成功完成。
- Agent 退出：结束等待状态并提供重连。已有消息保持可读；旧 session ID 不再直接使用，新对话在新连接中重新创建。
- 重连后需要继续旧会话时，显式调用 `session/load`；若失败，提示新建对话，不能悄悄创建无上下文会话冒充续聊。
- 初始化和创建会话使用有界超时；正常生成不设置固定的短超时，用户可以停止。
- 窗口关闭或应用退出时关闭连接并回收本应用启动的 Agent 子进程，持续读取 stderr 以免阻塞进程。

本版会话展示记录随应用退出清空。Aries 自己保存的上下文仍由 Aries 管理；本版不列出其他客户端的历史会话。当前 Aries 的 `session/load` 不回放历史消息，因此运行期间重连时使用已保留的展示记录。

## 代码职责

- `src/main.rs`：解析工作目录，初始化 GPUI，创建窗口与退出行为。
- `src/chat.rs`：会话、消息、草稿和请求状态；处理增量、完成、失败与取消。
- `src/acp.rs`：子进程、ACP 连接、请求与通知、重连和退出。
- `src/ui/`：导航栏、对话消息、输入框与状态展示。

协议事件通过类型明确的消息进入会话状态，状态不依赖 GPUI，便于测试增量和会话切换。

## 验证与验收

1. 状态测试覆盖：流式拼接、跨会话事件路由、连续两轮对话、停止后保留部分内容、空输入拒绝和断线后解除等待。
2. 协议测试使用受控的 stdio 测试 Agent，验证初始化、新建会话、早到通知、消息发送、取消、进程异常退出和清理。
3. 使用本机 `aries acp` 验证初始化与新建会话；交互验证发送一条简单问候并看到真实回复。
4. 运行格式检查、编译检查和测试，启动应用确认两栏布局、多行输入、会话切换、滚动及中文输入法行为。
5. 验收路径：启动 → 新建对话 → 发送 → 流式回复 → 第二轮追问 → 停止 → 新建另一对话 → 返回前一对话。
